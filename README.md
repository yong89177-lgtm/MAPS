# MAPS · 생산기술혁신센터 AI 플랫폼 — 백엔드 배포 가이드

`deploy/index.html`(프런트엔드)이 기대하는 `api/*` 백엔드를 **Vercel Serverless Functions + Vercel Blob**
으로 구현했습니다. 로그인/회원가입, 대시보드 등록요청 2단계 승인, 게시판·라운지·자료공유, 팝업·매뉴얼,
그리고 관리자 콘솔의 "HTML 업데이트"(포털 화면 자체 교체)까지 전부 동작합니다.

## 배포 절차 (최초 1회)

1. 이 저장소를 Vercel 프로젝트로 Import 합니다. (Framework Preset: **Other** 로 두면 됩니다 — 빌드 명령 없음)
2. Vercel 프로젝트 → **Storage** 탭 → **Create Database** → **Blob** 을 눌러 Blob Store 하나를 연결합니다.
   연결하면 `BLOB_READ_WRITE_TOKEN` 환경변수가 자동으로 추가됩니다.
3. **Settings → Environment Variables** 에 아래 값을 추가합니다.

   | 변수 | 값 | 설명 |
   |---|---|---|
   | `ADMIN_PASSWORD` | 원하는 초기 관리자 비밀번호 | 필수. 최초 배포 시 이 값으로 `admin` 계정이 자동 생성됩니다. |
   | `ADMIN_ID` | (선택, 기본값 `admin`) | 최초 관리자 아이디를 바꾸고 싶을 때만 설정 |
   | `BLOB_PATH_SECRET` | 32자 이상의 임의 문자열 | 필수. 데이터 저장 경로의 접두어로 써서, Blob이 "공개" 접근이어도 URL을 모르면 못 읽게 합니다. 아래 명령으로 생성하세요. |

   ```bash
   openssl rand -hex 32
   ```

   `BLOB_PATH_SECRET` 은 한 번 정하면 절대 바꾸지 마세요 — 바꾸면 기존에 저장된 모든 데이터(계정, 게시글 등)를 찾지 못합니다.

4. **Deploy**. 배포가 끝나면 사이트에 접속해 관리자 로그인(설정 톱니바퀴) → 위에서 설정한 `ADMIN_ID`/`ADMIN_PASSWORD` 로 로그인합니다.
5. 로그인 후 관리자 콘솔 → 계정 관리에서 `admin` 비밀번호를 다시 한번 원하는 값으로 바꿔두는 것을 권장합니다
   (환경변수의 `ADMIN_PASSWORD`는 계정이 이미 만들어진 뒤에는 더 이상 참조되지 않습니다).

이후 회원가입은 "승인 대기" 탭에서 관리자가 승인해야 로그인할 수 있습니다.

## 아키텍처 요약

- **데이터 저장**: 계정/게시글/댓글/라운지/자료공유/대시보드 상태/승인이력 등 모든 JSON 데이터와, 첨부파일·이미지·HTML 업로드 같은 바이너리를 전부 **Vercel Blob** 한 곳에 저장합니다 (`api/_lib/blob.js`). 브라우저에는 Blob의 실제 URL을 절대 노출하지 않고, 항상 `/api/*` 라우트가 서버에서 대신 읽어 스트리밍합니다.
- **세션/로그인**: 비밀번호는 `scrypt` 로 해시해 저장합니다. 로그인하면 서버가 무작위 세션 토큰을 발급해 Blob에 저장하고, 브라우저에는 `HttpOnly` 쿠키로만 토큰을 내려줍니다(JWT 아님 — 로그아웃 시 서버에서 즉시 폐기됩니다).
- **`data/dashboards.json`**: 원래 정적 파일이었던 이 경로를 `vercel.json` 리라이트로 `/api/dashboards-data` 함수에 연결해, 관리자 콘솔에서 저장한 대시보드 배치가 실제로 반영되도록 했습니다.
- **"HTML 업데이트" (포털 전체 교체)**: 원래 구조는 정적 파일 배포라 관리자가 새 HTML을 올려도 실제로 반영될 방법이 없었습니다. 이를 위해 **루트(`/`) 요청 자체를 `api/render.js` 서버리스 함수가 동적으로 응답**하도록 바꿨습니다 — Blob에 저장된 최신 HTML이 있으면 그것을, 없으면(최초 배포 시) 저장소에 포함된 `deploy/index.html`을 내려줍니다. 관리자가 업로드하면 이전 버전은 다운로드 가능한 이력으로 보관됩니다.
- **히어로 배경 동영상**: 원래 `deploy/index.html` 안에 base64로 통째로 박혀 있어 파일이 20MB였습니다. Vercel 서버리스 함수는 응답 4.5MB 제한이 있어 이 상태로는 `api/render.js`가 절대 응답할 수 없었기 때문에, 영상을 `hero-bg.mp4` 라는 별도 정적 파일로 분리하고 HTML에서는 그 경로만 참조하도록 고쳤습니다 (`deploy/index.html`은 이제 약 350KB).

## 알려진 제약사항 (설계상 트레이드오프)

- **첨부파일 업로드 용량**: 게시판/라운지/자료공유 화면은 "최대 100MB" 라고 안내하지만, 이 백엔드는 파일을 base64로 감싸 JSON 요청 본문으로 보내고, **Vercel 서버리스 함수는 요청 본문 자체가 4.5MB로 제한**되어 있습니다. 실제로는 파일당 대략 3MB 안팎까지만 올라갑니다. 진짜 100MB를 지원하려면 브라우저가 Blob에 직접 업로드하는 방식(Vercel Blob Client Upload)으로 프런트엔드까지 고쳐야 하는데, 이번 작업 범위에는 포함하지 않았습니다.
- **관리자 "HTML 업데이트"도 같은 이유로 4MB 제한**을 걸어뒀습니다. 큰 이미지/동영상은 문서에 base64로 넣지 말고 별도 파일이나 외부 링크로 참조하세요.
- **대시보드 타일 "장애/정상" 상태**: 사내망 전용 IP·주소는 Vercel(퍼블릭 클라우드)에서 접속성을 확인할 수 없어, 자동 헬스체크는 하지 않습니다. 관리자가 수동으로 걸어두는 "유예" 토글만 동작합니다.
- **읽기 지연 가능성**: 데이터를 바꾼 직후(다른 서버리스 인스턴스가 처리하는) 다음 요청에서 아주 짧은 시간(수 초) 동안 이전 값이 보일 수 있습니다(Blob 엣지 캐시 특성). 사내 소규모 포털 트래픽에서는 문제되지 않는 수준입니다.
- **대시보드 등록요청 승인 후 자동 배치는 하지 않습니다**: 2차 승인이 끝나면 상태가 "반영 완료"로 바뀌지만, 실제로 그리드에 타일을 추가하는 건 여전히 관리자가 "대시보드 관리" 탭에서 직접 해야 합니다.

## 원래 겪고 있던 문제와의 관계

"AI Agent 등록요청" 에서 HTML을 넣고 제출하면 "서버에 연결할 수 없습니다"가 뜨던 것은, `api/dash-request` 를
처리할 백엔드가 저장소에 아예 없었기 때문입니다(`api/*` 47종 전부 없었습니다). 이번 작업으로 그 요청을
포함한 전체 기능이 실제로 저장·조회·승인되도록 구현했습니다. 위 배포 절차대로 Vercel에 Blob을 연결하고
환경변수를 설정해야 실제로 작동합니다 — 코드만으로는 저장할 곳이 없어 여전히 실패합니다.
